# 제품 요구사항 정의서 (PRD) - Palzzi (팔찌)

## 1. 프로젝트 개요
* **프로젝트명:** Palzzi (팔찌)
* **버전:** v1.2 (최종본)
* **목적:** 미산가(일반/알파), 마크라메, 쿠미히모 등 다양한 실공예 패턴을 2D 평면 환경에서 시각적으로 시뮬레이션하고, 단계별 제작 과정을 가이드하며, 결과물을 도안 및 완성본 이미지로 저장·공유할 수 있는 웹 기반 통합 직조 플랫폼 구축.
* **개발 철학:** 1단계(MVP)에서는 복잡한 3D나 에디터 기능보다는 **템플릿 기반의 정확한 2D 수학적 직조 로직과 플레이백 제어**에 집중하며, 향후 3D 확장 및 커스텀 에디팅이 용이하도록 엔진 레이어와 UI 레이어를 철저히 분리(모듈화)하여 설계한다.

---

## 2. 개발 단계별 로드맵 (Phased Roadmap)

### Phase 1: MVP (최소 기능 제품) - 본 문서의 범위
* **핵심 기능:** 3대 공예(미산가, 마크라메, 쿠미히모)  중 쿠미히모 템플릿 라이브러리 구축, 2D 인터랙티브 플레이어(재생/일시정지/스텝 조절), 기호화된 도안(Pattern Chart) 및 완성 시각화(Finished View) 동시 렌더링, JSON 기반 로컬 저장, PNG/SVG 이미지 내보내기.
* **그래픽스:** 2D Flat Graphics (HTML5 Canvas 또는 라이브러리 활용).

### Phase 2: 확장 단계 (Future Scope)
* **그래픽스 고도화:** WebGL 및 `Three.js`를 도입하여 실의 섬유 질감, 두께감, 물리적 장력에 따른 입체적인 꼬임을 표현하는 3D 렌더링 뷰어 탑재.
* **기능 확장:** 사용자가 격자나 디스크를 직접 클릭하며 자신만의 독창적인 도안을 처음부터 설계할 수 있는 '커스텀 패턴 에디터' 모드 도입.

## 3. 공예별 핵심 메커니즘 및 기능 요구사항

### 3.1 쿠미히모 (Kumihimo)
* **지원 디스크 범위 (MVP):** 원형 디스크(Round Disk) 기반의 기본 8줄 및 16줄, 20줄, 24줄, 28줄, 32줄 브레이딩(Braiding) 패턴.
* **메커니즘:** 슬롯(Slot) 기반 원형 순열 데이터 모델. 예: '32번 슬롯의 실을 17번 슬롯으로, 16번 슬롯의 실을 1번 슬롯으로 이동'하는 상호 치환 연산 규칙 적용.
* **시각화:** 2D 원형 디스크 인터페이스 상에서 실이 배치된 상태를 보여주고, 현재 움직여야 하는 실과 이동 방향을 가이드 화살표(Arrow Animation)로 연출.

## 4. 기능 사양 (Functional Specifications)

### 4.1 템플릿 라이브러리 및 셀렉터 (Template Library)
* 사용자가 메인 진입 시 공예 종류(미산가/마크라메/쿠미히모)를 선택할 수 있는 탭 UI 제공.
* 선택한 공예 내에서 난이도별/스타일별 사전 정의된 템플릿 패턴 목록(예: 미산가 V자 패턴, 쿠미히모 8줄 기본 등) 제공.
* 템플릿 선택 시 해당 패턴의 총 실 개수, 기본 색상 배열, 총 시뮬레이션 단계 수 등의 메타데이터 로드.

### 4.2 시뮬레이터 플레이백 컨트롤 (Playback Control)
* **컨트롤러 UI:** 비디오 플레이어 형태의 컨트롤바 탑재.
  * 버튼 구성: `처음으로(⏮)`, `이전 단계(◀)`, `재생/일시정지(▶/⏸)`, `다음 단계(▶)`, `끝으로(⏭)`
  * 자동 재생 속도를 조절할 수 있는 배속 슬라이더(0.5x, 1.0x, 2.0x).
  * 현재 직조 진행 상황을 백분율(%) 및 스텝 수(예: Step 24 / 120)로 표시하는 진행 바(Progress Bar).

### 4.3 듀얼 실시간 뷰어 (Dual Rendering View)
시뮬레이션 재생 상태에 따라 화면은 실시간으로 동기화되는 두 개의 뷰(View)를 보여준다.
* **제작 도안 뷰 (Pattern Chart View):** 실제 공예가들이 도안을 읽는 방식에 맞춘 기호화된 차트 화면. 현재 진행 중인 행(Row) 또는 슬롯이 하이라이트 처리됨.
* **완성 시각화 뷰 (Finished View):** 현재 단계까지 매듭이 지어졌을 때, 완성되어 가는 실제 팔찌의 가상 형태를 평면 그래픽 선(Line)과 면(Polygon)의 조합으로 부드럽게 연결하여 가상 렌더링.

### 4.4 데이터 관리 및 내보내기 (Data & Export)
* **포맷:** 모든 패턴 정의 및 상태 데이터는 표준 JSON 구조로 관리.
* **저장(Save):** 사용자가 시뮬레이션 중인 상태나 마음에 드는 템플릿 커스텀 색상 상태를 브라우저 로컬 저장소(`LocalStorage`)에 저장하여 추후 '내 보관함'에서 재개 가능하도록 처리.
* **내보내기(Export):**
  * **도안 다운로드:** 인쇄 및 오프라인 참조가 가능하도록 전체 '기호화된 도안 차트'를 **고해상도 PNG** 또는 해상도 깨짐이 없는 **SVG 파일**로 내보내기 기능 제공.
  * **완성본 다운로드:** 완성 시각화 뷰의 캔버스 이미지를 추출하여 **PNG 파일**로 다운로드.
* **공유(Share):** 현재 상태의 패턴 식별값 및 색상 파라미터를 담은 고유 공유용 URL 생성 기능 제공.
  - **단축 URL:** `/s?t={templateId}&c={base64url_colors}&s={step}&k={patternKey}` 형식
  - 색상값은 base64url 인코딩으로 압축 (8색 기준 약 24자)
  - 기존 `?tmpl=...&colors=...` 형식도 하위 호환
* **갤러리(Gallery):** Firestore에 저장된 패턴을 갤러리 페이지(`/`) 및 시뮬레이터 사이드바에서 탐색. 좋아요, 정렬(최신순/좋아요순/내 좋아요순) 지원.
* **스냅샷:** 3D 뷰어 스냅샷을 `snapshotBase64`(base64 JPEG)로 Firestore에 저장. 빌드 시 정적 JPG 파일(`public/snapshots/{docId}.jpg`)로 생성되어 Firebase Hosting에서 직접 서빙.
* **좋아요(Like):** 인증 사용자는 Firestore 트랜잭션으로 영구 저장. 비로그인 사용자는 세션당 1회 제한(sessionStorage + sessionId 기반 Firestore 반영).

## 6. 추천 기술 스택 (Technical Architecture)
* **Front-end UI:** React.js 또는 Vue.js (컴포넌트 단위 상태 관리 및 도안-완성본 뷰 간의 reactive한 동기화 최적화)

* **Graphics Rendering Engine:** HTML5 Canvas API 전용 또는 Fabric.js / Pixi.js (수많은 선과 매듭 기호 노드를 가볍고 부드럽게 렌더링하기 위함)

* **State Management:** Zustand 또는 Redux Toolkit (플레이어 스텝 변화에 따른 실 색상 및 위상 배열 상태 추적용)

* **Storage & Sharing Infrastructure (MVP 선택):** Firebase (서버리스 환경에서 사용자 패턴 JSON 데이터 저장 및 공유 링크 메타데이터 관리를 빠르게 구현하는 데 최적화)
